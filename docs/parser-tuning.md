# Настройка парсера расписания

Парсер не привязан к конкретному формату PDF: он определяет структуру по
координатам текста и раскладывает данные на преподавателей и группы. Но
учебные заведения оформляют расписания по-разному, поэтому парсер (и его
конфигурация) рассчитаны на то, чтобы подстроиться под конкретный документ.

## Как парсер работает

```
PDF → извлечение текста → разметка страницы → выбор стратегии → занятия → преподаватели и группы
```

1. **Извлечение текста.** Сначала используется PDFium (`pdfrx`) — он даёт
   координаты каждого фрагмента. Если он не справился, включается резервный
   разбор на чистом Dart (`PureDartPdfTextExtractor`), который читает объекты,
   потоки, объектные потоки и таблицы `/ToUnicode`.
2. **Разметка страницы** (`PageLayout`): по профилю занятости страницы
   определяются вертикальные колонки таблицы, а строки раскладываются по этим
   колонкам. Широкие фрагменты (заголовок документа на всю ширину) из анализа
   колонок исключаются, чтобы не «склеить» страницу в одну колонку.
3. **Выбор стратегии** (по признакам страницы, с откатом к следующей):
   * `week-matrix` — дни недели стоят в шапке таблицы (шахматка «дни × пары»);
   * `table-columns` — классическая таблица с колонками «День / Пара / Время /
     Предмет / Преподаватель / Группа / Аудитория»;
   * `flat-text` — построчный разбор, когда табличной структуры нет вовсе.
4. **Сборка сущностей.** Каждое занятие попадает и в расписание преподавателя, и
   в расписание группы; дубликаты одной пары (например, для двух групп потока)
   склеиваются.

## Что можно настроить

Конфигурация живёт в `lib/data/parser/parser_config.dart` (`ParserConfig`):

| Параметр | Назначение |
| --- | --- |
| `teacherHeaders`, `groupHeaders`, `dayHeaders`, `pairHeaders`, `timeHeaders`, `subjectHeaders`, `roomHeaders` | Как называются колонки в вашем PDF. Добавьте свои варианты («Препод.», «Дисциплина», «Ауд.», «Класс») |
| `minColumnGap` | Минимальный зазор между колонками в пунктах. Если колонки «слипаются» — увеличьте (например до 12) |
| `columnPadding` | Допуск отнесения фрагмента к колонке |
| `maxColumns` | Защита от «дребезга»: если колонок оказывается слишком много, зазор автоматически увеличивается |
| `maxColumnWidthRatio` | Какие фрагменты не участвуют в поиске колонок (по умолчанию — шире 60 % страницы) |
| `defaultPairTimes` | Типовое расписание звонков: подставляется, если в PDF времени нет |
| `assumeDefaultPairTimes` | Включена ли подстановка типового времени (по умолчанию да; факт подстановки попадает в предупреждения) |

## Как подстроить парсер под конкретный PDF

1. Обновите расписание в приложении и откройте **Диагностика** (меню «⋮» на
   главном экране).
2. Посмотрите:
   * **«Извлечённый текст PDF»** — есть ли текстовый слой (если пусто, PDF —
     скан, и нужен OCR: приложение честно сообщит «В PDF не найден текстовый слой»);
   * **«Предупреждения парсера»** — что именно не распозналось (нет времени,
     нет преподавателей, нет групп);
   * **«Журнал»** — какой стратегией разобрано расписание и с какой уверенностью.
3. Нажмите «Скопировать» и сверьте текст с настройками колонок и шаблонами
   групп/ФИО в `parser_config.dart` и `cell_parser.dart`.
4. Если структуру не удалось распознать — упростите задачу: добавьте в
   `ParserConfig` заголовки колонок ровно так, как они написаны в PDF.

## Разбор текста ячейки

`CellParser` вытаскивает из строки предмет, преподавателя, группу и аудиторию
по эвристикам:

| Что ищем | Примеры, которые распознаются |
| --- | --- |
| Время | `08:30-10:00`, `8.30–10.00`, `08:30` |
| Номер пары | `1`, `2 пара`, `3 урок` |
| Аудитория | `ауд. 305`, `каб. 12а`, `№ 305`, `Математика 305` |
| Группа | `группа ИС-21`, `ИС-21`, `ПКС-19-2`, `21ИС` |
| Преподаватель | `Иванов Иван Петрович`, `Иванов И.И.` |
| Чётность недели | `числитель`, `знаменатель` |

Оставшийся текст считается названием предмета. Служебные подписи («ауд.»,
«гр.», «пара») из названия вырезаются.

## Известные ограничения

* **PDF-скан без текстового слоя** разобрать нельзя — нужен OCR, которого в
  приложении нет. Это осознанное решение: OCR на устройстве даёт много ошибок и
  сильно увеличивает размер приложения.
* **Сложные объединённые ячейки** с диагональным делением или вложенными
  таблицами могут разобраться частично: приложение покажет то, что поняло, и
  запишет предупреждение.
* **Недельная чётность**: если расписание делится на числитель/знаменатель,
  занятия попадут в расписание с пометкой чётности, но дневник показывает все
  занятия недели — фильтр по чётности не реализован.
* **Несколько занятий в одной ячейке** (например «Математика / Физика») могут
  склеиться в один предмет.

## Возможности для развития

Если понадобится точнее разбирать конкретный формат, точки расширения такие:

* `ScheduleParser` — добавить новую стратегию рядом с существующими
  (`_parseWeekMatrix`, `_parseTableColumns`, `_parseFlatText`);
* `ParserConfig` — вынести шаблоны в настройки приложения, чтобы не пересобирать
  приложение под каждую школу;
* `PageLayout` — заменить определение колонок на анализ линий таблицы
  (PDF-операторы `re`/`l` в потоке содержимого), если в документе есть
  нарисованная сетка.

## Тестирование парсера

Тесты не требуют настоящих PDF: страницы собираются синтетически
(`test/support/fakes.dart`, `test/data/pdf/pdf_fixtures.dart`).

```bash
flutter test test/data/parser
flutter test test/data/pdf          # включает тесты разбора настоящих PDF-байтов
```

Если у вас есть «эталонный» PDF расписания, самый быстрый путь — добавить его
текст (результат извлечения) как фикстуру и зафиксировать ожидаемый результат в
тесте: так изменение парсера сразу покажет регрессии.
