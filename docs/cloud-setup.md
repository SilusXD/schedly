# Настройка облачного хранилища

Приложение синхронизирует разобранное расписание между устройствами. Хранилище
необязательно: без него Schedly полностью работает локально, а при недоступности
облака данные берутся из локального кэша.

Поддерживаются два типа хранилищ:

| Тип | Что подходит | Что нужно |
| --- | --- | --- |
| **WebDAV** | Яндекс.Диск, Nextcloud, ownCloud | Логин и **пароль приложения** |
| **S3-совместимое** | Yandex Object Storage, MinIO, AWS S3, Google Cloud Storage / Firebase Storage | Адрес, регион, бакет, ключи |

## Структура файлов в хранилище

```
<базовая папка>/
├── schedule_2026-03-16.json    # разобранное расписание (преподаватели + группы)
├── schedule_2026-03-17.json
└── raw/
    ├── 2026-03-16.pdf          # исходный PDF (для повторного разбора)
    └── 2026-03-17.pdf
```

Имя JSON-файла соответствует дате расписания, поэтому любое устройство может
забрать нужный день без обращения к сайту учебного заведения.

## Вариант 1. WebDAV и Яндекс.Диск (рекомендуется для быстрого старта)

Почему так проще всего: не нужен ни аккаунт разработчика, ни консоль облачного
провайдера, ни SDK — только адрес сервера и пароль приложения.

1. Откройте [Яндекс ID → Безопасность → Пароли приложений](https://id.yandex.ru/security/app-passwords).
2. Создайте пароль для приложения типа **«Файлы» (WebDAV)**. Обычный пароль от
   аккаунта не подойдёт — нужен именно пароль приложения.
3. В приложении: **Настройки → Облачное хранилище**:
   * Хранилище — `WebDAV`;
   * Адрес сервера — `https://webdav.yandex.ru`;
   * Логин Яндекс.Диска — ваш логин (без `@yandex.ru` достаточно, но лучше указать полностью);
   * Пароль приложения — созданный пароль;
   * Папка в хранилище — `schedly` (можно оставить по умолчанию).
4. Нажмите **«Сохранить облако»**, затем **«Выгрузить сейчас»** — так вы сразу
   проверите, что доступ работает.

### Nextcloud / ownCloud

Адрес сервера: `https://cloud.example.com/remote.php/dav/files/ЛОГИН`, тип —
`WebDAV`, логин и пароль приложения — из настроек безопасности Nextcloud.

### Как это устроено внутри

* Проверка и создание папки — `MKCOL`, список файлов — `PROPFIND` (Depth: 1),
  чтение — `GET`, запись — `PUT`, удаление — `DELETE`.
* Авторизация — HTTP Basic поверх HTTPS.
* Ответы `PROPFIND` разбираются как XML; коллекции (папки) отфильтровываются.

## Вариант 2. S3-совместимое хранилище

Адаптер подписывает каждый запрос по **AWS Signature Version 4** (реализация —
`lib/data/cloud/sigv4.dart`, покрыта юнит-тестами).

### Yandex Object Storage

| Поле | Значение |
| --- | --- |
| Адрес сервера | `https://storage.yandexcloud.net` |
| Регион | `ru-central1` |
| Бакет | имя вашего бакета |
| Key ID / Secret key | статический ключ доступа сервисного аккаунта |
| Адресация path-style | **включена** |

1. В консоли Yandex Cloud создайте сервисный аккаунт с ролью `storage.editor`.
2. Создайте для него **статический ключ доступа** — это и есть Key ID/Secret.
3. Создайте бакет (например `schedly-schedule`).
4. Статический ключ имеет смысл ограничить политикой доступа только к нужному
   бакету: секрет хранится в Keychain устройства, но лучше ограничить его
   возможности на стороне облака.

### MinIO и другие self-hosted S3

Адрес — `https://minio.example.com`, регион — любой (например `us-east-1`),
адресация **path-style обязательна**.

### AWS S3

Адрес — `https://s3.eu-central-1.amazonaws.com`, регион — `eu-central-1`,
адресация virtual-hosted (path-style выключить), ключи IAM с доступом только к
одному бакету.

### Firebase Storage и Google Cloud Storage

Отдельный SDK Firebase приложению не нужен: файлы Firebase Storage лежат в
бакете Google Cloud Storage, а GCS поддерживает **совместимый с S3 XML API** и
**HMAC-ключи** ([документация Google Cloud](https://docs.cloud.google.com/storage/docs/interoperability),
[HMAC keys](https://docs.cloud.google.com/storage/docs/authentication/hmackeys)).

| Поле | Значение |
| --- | --- |
| Адрес сервера | `https://storage.googleapis.com` |
| Регион | `auto` |
| Бакет | `<проект>.firebasestorage.app` или `<проект>.appspot.com` |
| Key ID / Secret key | HMAC-ключ сервисного аккаунта |
| Адресация path-style | **выключена** (virtual-hosted) |

Как получить ключи:

1. В Google Cloud Console откройте **Cloud Storage → Settings → Interoperability**.
2. Если режим совместимости ещё не включён — включите его для проекта.
3. Создайте **ключа доступа** (Access key) для сервисного аккаунта: получите
   `Access key` (это Key ID) и `Secret` (это Secret key).
4. Сервисному аккаунту нужна роль с правом записи в бакет (например
   `Storage Object Admin`).
5. Правила безопасности Firebase Storage (Rules) на XML API не влияют: доступ
   контролируется правами IAM самого сервисного аккаунта, поэтому ключ стоит
   выдавать только на нужный бакет.

Почему так, а не через `firebase_storage`:

* не нужно добавлять `GoogleService-Info.plist` и нативные зависимости Firebase
  в iOS-сборку (меньше риск, что сборка на `macos-latest` упадёт);
* один и тот же код работает и с Firebase, и с Яндекс.Облаком, и с MinIO;
* проще тестировать: подпись запросов проверяется юнит-тестами.

## Как приложение выбирает данные

Порядок действий при обновлении (`OfflineFirstScheduleRepository.refresh`):

1. Скачать PDF за сегодня; если файла нет — проверить предыдущие даты
   (по умолчанию до 6 дней назад).
2. Разобрать PDF и сохранить результат в **локальный кэш**.
3. Выгрузить JSON (и исходный PDF) в **облако** — если оно настроено и включена
   автоматическая выгрузка.
4. Если шаги 1–2 не удались — показать последнее расписание **из локального кэша**.
5. Если кэша нет — попробовать забрать JSON **из облака**.
6. Если данных нет нигде — показать «Расписание недоступно», не удаляя то, что
   уже сохранено на устройстве.

Ошибка облака никогда не мешает обновлению расписания: она только добавляет
строку в журнал диагностики.

## Безопасность

* Секретный ключ (или пароль приложения WebDAV) **не хранится** в локальной базе
  Hive — он лежит в iOS Keychain (`flutter_secure_storage`).
* Адрес, логин, бакет и папка хранятся в Hive — это не секреты.
* Заметки и домашние задания не выгружаются в облако вообще: это личные записи
  и они остаются на устройстве.
* Приложение по умолчанию разрешает произвольные сетевые загрузки
  (см. `NSAppTransportSecurity` в `ios/Runner/Info.plist`), потому что школьные
  сайты часто отдают PDF по `http`. Если ваш сайт работает только по `https`,
  ключ `NSAllowsArbitraryLoads` можно убрать.

## Частые проблемы

| Симптом | Причина | Решение |
| --- | --- | --- |
| «WebDAV отклонил авторизацию» | Использован обычный пароль аккаунта | Создать и указать **пароль приложения** |
| `SignatureDoesNotMatch` (S3) | Неверный регион или тип адресации | Уточнить регион; для MinIO и Yandex включить path-style |
| `403` при записи в Firebase Storage | У сервисного аккаунта нет прав | Выдать роль `Storage Object Admin` на бакет |
| Файлы не видны в облаке | Другая «Папка в хранилище» на другом устройстве | Указать одинаковое значение на всех устройствах |
| Синхронизация не выполняется | Облако не сохранено или не заполнены поля | Нажать «Сохранить облако» и проверить «Выгрузить сейчас» |
