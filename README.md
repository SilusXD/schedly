# Schedly — дневник расписания

Flutter-приложение для iOS, которое скачивает PDF с расписанием занятий,
разбирает его по преподавателям и группам и показывает в виде привычного
бумажного дневника: две колонки (Пн–Ср и Чт–Сб), внутри дня — пары с полями для
домашнего задания и личных пометок.

Приложение работает **offline-first**: при недоступности сайта учебного заведения
или облака показываются сохранённые данные, а не пустой экран.

## Возможности

* **Загрузка PDF по ссылке с датой.** Шаблон вида
  `https://school.ru/schedule_{yyyy-MM-dd}.pdf`; поддерживаются разные форматы
  даты, при отсутствии файла за сегодня проверяются предыдущие дни.
* **Разбор PDF на устройстве.** Дни недели, номера пар, время, предметы,
  преподаватели, группы и аудитории; три стратегии разбора (матрица «дни × пары»,
  таблица с колонками, плоский текст) выбираются автоматически.
* **Два списка.** Вкладки «Преподаватели» и «Группы» с поиском по имени.
* **Дневник.** Две колонки дней; под каждой парой — поле домашнего задания,
  отметка «выполнено» и заметка.
* **Оффлайн-режим.** Локальный кэш расписаний и заметок, баннер оффлайн-режима,
  понятные сообщения о причинах сбоя.
* **Облачная синхронизация.** WebDAV (Яндекс.Диск, Nextcloud) или
  S3-совместимое хранилище (Yandex Object Storage, MinIO, AWS S3,
  Google/Firebase Storage). Облако необязательно.
* **Диагностика прямо в приложении.** Журнал событий, предупреждения парсера и
  извлечённый текст PDF — без Mac и без Xcode.

## Требования

* Flutter **3.41.6** (stable) и Dart 3.11+
* Для сборки под iOS — macOS с Xcode; в проекте настроена сборка на
  `macos-latest` в GitHub Actions, поэтому локальный Mac не обязателен
* Для установки на iPhone — SideStore/AltStore/Sideloadly (см.
  [docs/ios-signing-sidestore.md](docs/ios-signing-sidestore.md))

## Быстрый старт

```bash
flutter pub get
flutter analyze
flutter test
flutter run          # на подключённом устройстве или симуляторе (macOS)
```

При первом запуске откройте **Настройки** (меню «⋮» на главном экране) и укажите
шаблон ссылки на PDF — без него расписание загрузить нечего:

```
https://school.ru/schedule_{yyyy-MM-dd}.pdf
```

Поддерживаемые плейсхолдеры: `{yyyy}`, `{yy}`, `{MM}`, `{M}`, `{dd}`, `{d}`,
`{yyyy-MM-dd}`, `{dd.MM.yyyy}`, `{dd-MM-yyyy}`, `{yyyyMMdd}`, `{dd_MM_yyyy}`.

Кнопка **«Проверить ссылку»** выполняет HEAD-запрос (с резервной проверкой через
`GET` с `Range`) и сразу показывает, найден ли файл на сегодня.

## Поддержка расписаний КИП Фин.университета

Приложение умеет работать не только с шаблоном ссылки, но и со **страницей-каталогом**
(по умолчанию `https://www.fa.ru/kip/students/schedule.php`). Это нужно потому, что имя
файла на той странице содержит случайный хеш (`/upload/constructor/<hex>/<hash>/…`),
который меняется при каждой публикации, — собрать ссылку по дате невозможно.

Как это работает:

1. Приложение скачивает страницу и достаёт из неё ссылки: ежедневное «общее»
   расписание (`Расписание на 26.09.2026`) и полугодовые файлы по курсам.
2. Из ежедневного файла берутся **группы, аудитории и замены** (формат — матрица
   «преподаватель × пара»).
3. Из полугодового — **названия предметов и плановые преподаватели** (формат —
   матрица «группа × пара»; одна ячейка может содержать две записи: нечётная и
   чётная недели).
4. Данные объединяются по ключу «день недели + номер пары + группа»: приоритет у
   ежедневного файла, расхождение преподавателя помечается как **замена**.
5. Полугодовое расписание кэшируется на сутки — оно меняется редко, а ежедневный
   файл запрашивается при каждом обновлении.

Адрес страницы настраивается: **Настройки → Страница с расписанием**. Если поле
очистить, приложение вернётся к резервному способу — шаблону ссылки с датой.


Сборка выполняется в GitHub Actions на `macos-latest` без подписи, а подпись
происходит уже на устройстве:

```bash
# то, что делает workflow .github/workflows/ios.yml
flutter build ios --release --no-codesign

mkdir -p Payload
cp -R build/ios/iphoneos/Runner.app Payload/
zip -qry Schedly-unsigned.ipa Payload
```

Готовый `Schedly-unsigned.ipa` скачивается со страницы запуска workflow
(раздел *Artifacts*) и устанавливается через SideStore.

* Пошаговая инструкция по подписи и установке без Mac и без платного аккаунта
  разработчика: [docs/ios-signing-sidestore.md](docs/ios-signing-sidestore.md)
* Разбор типичных ошибок установки и запуска:
  [docs/ios-troubleshooting.md](docs/ios-troubleshooting.md)

Шаблон ссылки можно «зашить» в сборку на этапе CI: у workflow есть входной
параметр `schedule_url_template`.

## Облачная синхронизация

Кратко: **Настройки → Облачное хранилище**. Поддерживаются WebDAV (проще всего —
Яндекс.Диск с паролем приложения) и S3-совместимые хранилища. Firebase Storage
подключается без Firebase SDK — через совместимый с S3 XML API и HMAC-ключи
Google Cloud Storage.

Подробности, включая структуру файлов и разбор ошибок:
[docs/cloud-setup.md](docs/cloud-setup.md).

## Если расписание не разбирается

Откройте **Диагностика** (меню «⋮»): там видно извлечённый текст PDF,
предупреждения парсера и журнал с выбранной стратегией разбора. Как подстроить
парсер под конкретный формат: [docs/parser-tuning.md](docs/parser-tuning.md).

## Логика получения данных

1. Скачать PDF за сегодня; если файла нет — проверить предыдущие даты.
2. Разобрать PDF, обновить локальный кэш и (при настройке) облако.
3. Если PDF недоступен — показать последнее расписание из локального кэша.
4. Если кэша нет — забрать JSON из облака.
5. Если данных нет нигде — сообщить «Расписание недоступно», ничего не удаляя.

## Тесты

```bash
flutter test                                   # всё
flutter test test/data/parser                  # парсер расписания
flutter test test/data/cloud                   # подпись AWS SigV4
flutter test test/data/repositories            # offline-first логика и откаты
```

Тесты не требуют настоящих PDF: страницы собираются синтетически
(`test/support/fakes.dart`, `test/data/pdf/pdf_fixtures.dart`), а модуль разбора
чистого Dart проверяется на PDF-байтах, сгенерированных прямо в тесте.

## Ограничения

* PDF-сканы без текстового слоя не поддерживаются: нужен OCR, которого в
  приложении нет (приложение честно сообщает об этом).
* Заметки и домашние задания хранятся только на устройстве и в облако не
  выгружаются.
* Расписание делится на числитель/знаменатель: пары разбираются и помечаются, но
  фильтра по чётности недели в дневнике пока нет.
* Приложение предназначено для личного использования и устанавливается
  сайдлоадом (бесплатный Apple ID → переподпись раз в 7 дней).
